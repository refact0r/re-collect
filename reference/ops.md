# Ops & Infrastructure

Notes on external configuration that isn't visible from the codebase.

## App worker (Cloudflare)

- Deploy: `pnpm run deploy:app` (builds then `wrangler deploy`). `pnpm run deploy` deploys the Convex backend first, then the app (`pnpm deploy` without `run` is a pnpm built-in — use `run`).
- `PUBLIC_CONVEX_URL` is baked into the bundle at build time. The production value comes from the checked-in `.env.production`, which overrides `.env.local` during `vite build` — local dev values can't leak into a deploy.
- The worker has no secrets: accounts, passwords and sessions live in Convex (see `reference/multi-user.md`).

## Convex env vars

Set with `npx convex env set <name> <value>`, list with `npx convex env list`.

- `R2_PUBLIC_URL` — base URL for the public R2 custom domain (no trailing slash). Used in `getImageUrl()` as `${R2_PUBLIC_URL}/${imageKey}`.
- `R2_TOKEN`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_ENDPOINT`, `R2_BUCKET` — required by `@convex-dev/r2`. See `reference/convex-r2.md`.
- `CLOUDFLARE_SCREENSHOT_URL` — public URL of the screenshot worker.
- `CLOUDFLARE_SCREENSHOT_KEY` — bearer token the screenshot worker checks. Must match the worker's `API_KEY` secret.
- `OPENROUTER_API_KEY` — required for AI image tagging. Used by `lib/tagger.ts` (the `taggingActions` runs) against `https://openrouter.ai/api/v1/chat/completions`.
- `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN` — Workers AI, for item embeddings (`lib/embedder.ts`, `@cf/google/embeddinggemma-2`). The token needs only Workers AI Read + Edit. Without them nothing embeds, and semantic search falls back to keyword results. After setting them on a deployment (or after an `EMBEDDING_MODEL` change), embed the existing items with `npx convex run embeddings:backfill` (add `--prod` for production).
- `TAGGING_MODEL` — optional. Defaults to `openai/gpt-6-luna`. Override to swap models without a code change.
- `ARENA_TOKEN` — optional. An Are.na personal access token for the discovery feed's channel polls (`lib/discoverySources.ts`); without it they run as a guest, limited to 30 requests a minute per (shared) Convex IP.

## Cloudflare R2

- Bucket name: `re-collect`.
- Public access via custom domain **`r2.refact0r.dev`** (set in R2 dashboard → bucket → Settings → Custom Domains).
- Why public + custom domain instead of presigned URLs: stable URLs mean browser and Cloudflare edge caches work properly; presigned URLs change per-fetch and break caching. Keys are unguessable UUIDs/timestamped paths so the privacy tradeoff is small.
- Image key conventions:
  - **Screenshots:** `screenshots/{itemId}-{timestamp}.webp` — new timestamp every call so retries always get a fresh key.
  - **og:images** (`linkImageMode: 'og'`): `og/{itemId}-{timestamp}.{ext}`, extension from the image's content type.
  - **Uploads:** UUID at bucket root (no prefix), generated by the R2 component.
- **Dev and prod share this bucket**, and dev's items are copies of prod's (same ids, same image keys). Deleting or re-capturing an item on dev deletes the object prod's copy points at. Seen 2026-11-14: Stripe Dot Dev's screenshot was gone at origin on both, still showing only from Cloudflare's edge cache. To check a key at origin, bypass the cache with a query string (`curl -I "https://r2.refact0r.dev/<key>?x=1"`).
- **Never overwrite an existing R2 key.** Objects are immutable; the cache rule below assumes this. `screenshots.setCompleted` deletes the previous key before writing a new one to enforce it on retries.

## Cloudflare Cache Rule

Zone `refact0r.dev` → Caching → Cache Rules → "R2 image caching":

- **Match:** Hostname equals `r2.refact0r.dev`
- **Cache eligibility:** Eligible for cache
- **Edge TTL:** Ignore cache-control, use **1 year**
- **Browser TTL:** Override origin, use **1 year**

Every URL on this hostname is content-addressable and never mutates (see invariant above), so 1-year TTLs are safe and keep repeat loads instant.

Cache invalidation:

- **Edge:** Cloudflare → Caching → Purge Cache (by URL or "Purge Everything"). Takes seconds.
- **Browser:** Can't be remotely invalidated. Use hard reload (Cmd/Ctrl-Shift-R), or change the URL (different key = new cache entry). For planned migrations, lower the Browser TTL on the rule a few weeks ahead so old TTLs roll over before you switch.

## Cloudflare Worker (screenshot)

- Source: `workers/screenshot/`. Deploy: `pnpm run deploy:screenshot` (from repo root).
- Bindings (`wrangler.toml`): `BROWSER` (Browser Rendering), `R2_BUCKET` (bound to `re-collect`).
- Secret `API_KEY`: set via `pnpm exec wrangler secret put API_KEY` in `workers/screenshot/`. Must match `CLOUDFLARE_SCREENSHOT_KEY`.

## Browser extension

- Source: `extension/` (see its README). Loaded unpacked, not published to a store.
- Configured in its options page with the Convex deployment URL (`.convex.cloud`) and an extension token, stored in `chrome.storage.local`. The token is a per-user session from "copy extension token" on the app's account page (see `reference/multi-user.md`). `users:signOut` revokes it along with the user's other sessions.
- Talks to Convex's HTTP API directly, so the backend needs no extension-specific config. Image saves and extension screenshots need the `imageImport` actions deployed.
